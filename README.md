# bbrlg_dump

Слепок рейтинга с [boberlogs.top](https://boberlogs.top) для WoW Circle, одним
файлом. Отсюда его забирает аддон **DmdrBoberLogsInfo** и показывает игроку
справку о другом игроке прямо в чате игры.

Репозиторий держит **один файл и один коммит**. Дамп пересобирается целиком при
каждом обновлении, поэтому история ему не нужна: старые слепки никому не
пригодятся, а полтора мегабайта в день превратились бы за год в сотни
мегабайт, которые каждый клиент тянул бы при клоне.

## `boberlogs.lua`

WoW 3.3.5 не умеет читать файлы в рантайме, поэтому данные попадают в клиент
единственным способом — Lua-таблицей, выполняемой при загрузке.

```lua
DmdrBoberLogsMeta = {
    season = "3", baked = "2026-07-29T17:22:38Z", complete = false,
    bosses = { "surf", "prof", "lich" }, seasons = { "3" },
}

DmdrBoberLogs = {
["Abuza"]="Druid@3,275,26-07-03,Balance,1,19902,,-,99,1,,,-,,,,,-,,",
["Adrianlee"]="Paladin@3,270,26-07-24,Protection,6,,12916,+,92,6,,,-,,,,,-,,",
}
```

**Ключ — ник, и это уже хэш-таблица.** `DmdrBoberLogs[имя]` ищется за O(1)
силами самой виртуальной машины, своего индекса строить не надо.

### Шаблон значения

```
class @ season, gs, last, spec, raids,
        surf_dps, surf_hps, surf_tank, surf_parse, surf_n,
        prof_dps, prof_hps, prof_tank, prof_parse, prof_n,
        lich_dps, lich_hps, lich_tank, lich_parse, lich_n
      @ следующий сезон тем же набором
```

| Поле | Что это |
|---|---|
| `class` | класс персонажа, один на все сезоны |
| `season` | номер сезона |
| `gs` | гирскор, **максимум** за сезон |
| `last` | дата последнего кила, `ГГ-ММ-ДД` |
| `spec` | спек, в котором чаще всего ходил в этом сезоне |
| `raids` | сколько **разных** рейдов отходил |
| `*_dps` | средний ДПС по боссу (по килам в роли дамагера) |
| `*_hps` | средний ХПС по боссу (по килам в роли хила) |
| `*_tank` | `+` — был на убийстве танком, `-` — не был |
| `*_parse` | средний парс, 0–100 |
| `*_n` | сколько раз убил этого босса, в любой роли |

Разделителей два: `@` между классом и сезонами и между сезонами, `,` внутри
сезона. Разбор в Lua — два split без всякого состояния.

### Что важно не перепутать

- **Роль спрятана в имена колонок, а не в отдельные записи.** Паладин, который
  во вторник лечил, а в пятницу танковал, — это одна запись, где заполнены и
  `surf_hps`, и `surf_tank`. Пример выше (`Adrianlee`) ровно такой.
- **У танка нет числа, только `+`/`-`.** ДПС танка не отвечает ни на один
  вопрос, а «был ли он там, когда босса убили» — отвечает на единственный.
- **Пусто — это «килов нет», а не ноль.** Ноль означал бы, что пришёл и ничего
  не выдал.
- **`gs` — максимум, а не среднее.** Шмот за сезон только улучшается, среднее
  тянуло бы к первой неделе.
- **`*_n` показывает, чему верить.** Среднее по одному килу — это не среднее.
- **`complete = false` значит, что обход неполный.** Отсутствие ника при этом
  значит «ещё не дошли», а не «не рейдил».

## Откуда берётся

Собирает `cmd/boberdump` из репозитория `mcp_pack`: обходит рейтинг постранично
по трём боссам и трём ролям, складывает сырые килы в SQLite и выгружает из неё
этот файл. Сезоны копятся: прошлый — законченная запись, его строки не
трогаются.

Обход **медленный намеренно**. Сайт отвечает 2–5 секунд на страницу и выдаёт
HTTP 429 на любую попытку торопиться — проверено: 24 соединения дали 1,9
запроса в секунду, 48 дали 1,2, а закончилось всё блокировкой. Поэтому раннер
идёт ровным ручейком (15 страниц в минуту), помечает каждую забранную страницу
и продолжает с того же места после перезапуска.

Данные публичные: те же числа отдаёт открытый API сайта любому желающему.
